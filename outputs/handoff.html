Estados y recorridos

Pagado registra una transferencia simulada. Por revisar exige una decisión humana. Rechazado detiene el flujo. El conjunto inicial muestra 2, 4 y 2 respectivamente.

  1. Políticas: Reglas → mover, añadir o editar criterio → Guardar reglas → Facturas → Procesar de nuevo. Los pagos anteriores quedan conservados.
  2. Ingreso: Añadir factura → seleccionar PDF/PNG/JPG → escaneo simulado → revisar o completar datos → Guardar y procesar factura.
  3. Cuenta nueva: INV-07 → comparar datos → comentario opcional → Aprobar, añadir cuenta y pagar → confirmar → nota y cuenta añadida al proveedor. Cancelar no ejecuta; rechazar no incorpora la cuenta.
  4. Proveedor: directorio → Añadir proveedor o Editar ficha → datos, lista autorizada y monedas → guardar → gestionar cuentas/notas y abrir correos.
  5. Conversación: Bandeja de correos → hilo → responder o reenviar; también redactar, guardar borrador, archivar, restaurar o marcar no leído.
  6. Tasa: detalle pendiente o menú → Tasas → buscar monedas → valor y fuente → Guardar tasa de hoy → procesar pendientes cuando corresponda.

Comentarios y recuperación

Las sugerencias nunca se eligen automáticamente. El comentario puede editarse o dejarse vacío; el registro conserva «Sin comentario adicional». Ayuda: «Añadir contexto ayuda a entender esta decisión cuando se revise más adelante».

Las búsquedas vacías explican que no hay coincidencias. Escaneo no reconocido ofrece formulario manual; una tasa faltante ofrece entrada manual con fuente. Las acciones usan texto, foco visible y controles nativos. Los errores se comunican con texto; el estado nunca depende solo del color.

En móvil, columnas de reglas, proveedor y correo se apilan. El selector permite mover criterios sin arrastrar. Las acciones de reglas vuelven al flujo normal para no cubrir las tarjetas. El detalle prioriza la decisión; la navegación conserva acceso a todos los módulos.

Datos, historial y límites

El estado local conserva facturas, reglas versionadas, proveedores, tasas, decisiones humanas, pagos simulados, mensajes y notas. Cada decisión mantiene las condiciones evaluadas; los eventos se acumulan. Una cuenta añadida al aprobar conserva las anteriores. Reprocesar nunca vuelve a ejecutar pagos registrados.

Los códigos internos de estado se mantienen por compatibilidad; la interfaz utiliza exclusivamente los tres nombres acordados. Guardar reglas no cambia decisiones hasta procesar de nuevo. Una falta de conversión deja revisión cuando no existe un motivo definitivo de rechazo. El archivo de ejemplo inicial mantiene tasas sintéticas de 2026-10-01; las nuevas tasas manuales usan el día local actual.

La consulta externa opcional usa ExchangeRate-API, con atribución visible. No se integra un banco, buzón, OCR ni verificación de identidad. localStorage no es un registro de auditoría inmutable. «Restaurar ejemplos» borra explícitamente los cambios locales de la dirección abierta.

Requisitos para pagar

Antes del tablero se muestran todos los criterios activos, sus valores y monedas aplicables. Cumplirlos todos permite pasar automáticamente a Pagado. Si alguno falla, se aplica Por revisar o Rechazado según el tablero; las excepciones requieren decisión humana. Una tasa válida y un proveedor no excluido son condiciones permanentes.
